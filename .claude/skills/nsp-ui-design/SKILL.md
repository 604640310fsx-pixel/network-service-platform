# NSP UI 设计

## 启用与权威

- 只在当前 Task Packet 明确要求本 skill 时使用。它不授予写入、工具、安装、外部访问、产品裁决或发布权限；按 Packet 指定的 `DESIGN` 或 `IMPLEMENT_UI` 模式工作。
- 先核对当前任务、目标页面、用户、主要使用场景、已批准的视觉与业务事实，以及允许修改的范围。以仓库根目录的 `CLAUDE.md`、`docs/ai/GPT-CONTROL-V2.md`、`docs/team/TEAM-COLLAB-V1.md` 和 `docs/ai/NSP-PROJECT-KNOWLEDGE.md` 为权威入口；只加载与该页面有关的冻结材料。不要把历史提案、未合并 PR 或此 skill 当成新的冻结事实。
- 若当前环境没有本 skill 或 Task Packet 所需的工具，说明缺失及受影响步骤，按管理链返回；不得自行安装、下载、初始化、改权限或换路径冒充已使用。

## 先判断页面承担什么工作

先用一句话写明页面的首要任务，再决定信息密度与视觉节奏。同一产品可同时有多种场景，不套用单一的「仪表盘风格」。

| 场景 | 首要问题 | 优先组织方式 |
| --- | --- | --- |
| 营销 / 获客 | 访客为什么相信、下一步做什么 | 清楚的主张与行动、可核实的证明、由浅入深的叙事节奏 |
| 运营 / 监控 | 现在是否异常、哪里需要处理 | 状态、变化、例外和下一动作优先；密度服务于扫读与定位 |
| 产品 / 工作流 | 用户怎样完成当前任务 | 任务路径、反馈、错误与恢复；逐步呈现必要信息 |
| 阅读 / 文档 | 怎样连续理解复杂内容 | 稳定的文字层级、合适行长、段落节奏、导航与注释 |
| 展示 / 大屏 | 远距离能否快速读懂 | 少量强信号、足够大的标签与数字、清晰的分组和对比 |

混合页面先定主场景；其他场景只服务主任务。例如公开监控内容可能兼有说明与数据，客户工作台可能兼有阅读与操作。不要因页面含数据就自动铺满卡片，也不要因页面面向访客就牺牲真实信息的可读性。

## 设计推演

1. **建立约束。** 列出已批准的字体、颜色、层级、交互、响应式规则、产品事实与禁止变更。区分已冻结事实、当前观察、尚未批准的提案。对未冻结的关键视觉方向先给可比较的提案与取舍，等待当前有权角色批准；日常间距、排版和局部视觉细节可在获准范围内独立决定。
2. **安排构图与比例。** 先确定视觉中心、阅读起点、主要行动和信息分组，再选栅格、对齐与容器宽度。用不同尺度表达主次，让重要内容获得面积和位置；不把所有模块做成等大的盒子。留白要帮助辨认关系、停顿和重点，避免平均分配或只靠装饰制造“高级感”。
3. **建立文字层级。** 标题、导语、正文、数据、标签和辅助说明各有职责。用字重、字号、行高、行长与间距形成可扫读的层级；保留既定字体和业务用语。长文、表格、数字与状态各按其阅读方式排版，不用一套标题比例覆盖所有场景。
4. **控制色彩与图像。** 颜色先表达品牌、状态、优先级与交互，再承担气氛。检查文字与状态的对比、颜色以外的辨认线索及不同主题。图片、图表、插画或图标应提供证据、方向或情绪价值；需要素材但缺少授权来源时提出占位需求，不编造真实客户、节点、价格或线路事实。
5. **编排内容节奏。** 交替使用概述、细节、证据、行动与适当的安静区域，让用户知道下一眼看哪里。卡片、边框、阴影、渐变、装饰图形可以使用，但每个都应承担分组、提示或叙事作用；避免无差别卡片阵列和可替换品牌名的模板外观。
6. **设计响应式行为。** 对桌面、平板和手机分别决定哪些内容保持、重排、折叠或延后；维护相同的信息优先级与任务路径。检查长标题、长数值、图表、导航、表单、空态和错误态；避免仅把桌面缩小，避免横向滚动遮蔽主要操作。
7. **完成细节。** 核对对齐、间距、边界、图标、微文案、焦点与悬停反馈、加载和禁用状态。动效应帮助理解状态变化，尊重减少动态效果的偏好。局部精修不得暗中改变已经批准的关键视觉、交互或业务事实。

设计新方向时，说明选择背后的场景、层级和取舍，而不是只提供形容词。若冻结结构无法承载目标，按 `CLAUDE.md` 报告缺口，不自行改变公共契约或产品流程。

## 工具与验证边界

- Impeccable 仅在当前环境实际可用且本任务允许时作为视觉审阅或精修辅助；先确认其真实能力，再用于当前页面的构图、比例、层级与细节。没有调用就不要声称使用过；不可用时继续已授权的本地设计工作，并如实报告缺失，不安装或扩权。
- `DESIGN` 阶段交付具体方案、差异、依据和待批准的关键决定，保持 `PROPOSAL`。只有当前 Packet 授权 `IMPLEMENT_UI` 时才改产品代码；已冻结视觉下只做获准的局部优化，不借“精修”引入新方向。
- 后续获准实施的验收必须查看实际运行页面截图，覆盖 Packet 指定的视口、主题和关键状态；把截图中观察到的层级、比例、溢出、对齐、内容及交互偏差逐项核对并修正。构建成功、静态代码审阅或自评分数不能替代截图证据。无法取得截图时标为 `NOT_RUN` 或 `UNVERIFIED`，不得声称视觉已验证。

## 交付格式

简要交代：页面主场景与用户任务；遵守的冻结事实；构图、文字、色彩、图像、节奏与响应式的具体选择；仍待批准的关键方向；实际使用的工具与实际截图/验证结果。仅报告当前 Task Packet 内的事实与动作，按 `TEAM-COLLAB-V1` 交接。
