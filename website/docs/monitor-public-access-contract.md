# 监控公网访问契约

## 1. 文档状态

- 状态：待架构与运维审阅。
- 范围：定义网站嵌入 `prod-monitor-3002` 时，浏览器、网站托管层、公网入口、出站连接器和内网监控服务之间的责任边界。
- 性质：仅为非执行性契约，不包含可直接运行的反向代理、隧道、systemd、DNS 或网络配置。
- 不在本文件中裁决：托管应用隧道与自有公网 VPS 方案的最终选择、真实域名、认证策略、连接器安装位置及上线时间。
- 本文件不得替代部署变更单、密钥管理流程或生产验收记录。

## 2. 已确认事实与约束

1. `prod-monitor-3002` 是当前正式监控界面的逻辑别名；现有页面、颜色、功能和移动端行为是网站嵌入的产品基准。
2. `recovery/prod-monitor-3002/2026-08-10/raw/` 是不可修改的生产恢复证据，不是开发目录，也不是部署源。
3. `monitoring/` 在 Website—3002 映射工作流中保持冻结；本工作流不修改监控页面、API 或运行配置。
4. 用户本地中国宽带不具备独享固定公网 IP，且可能处于动态公网地址或 CGNAT 环境。架构不得要求公网主动连接家庭网络，不得依赖家庭入站端口、端口映射或 DDNS。
5. 网站是静态 React/Vite SPA；监控页面通过 iframe 直接加载独立的 HTTPS 公网 origin。两个页面在浏览器安全模型中属于不同 origin。
6. 恢复版监控页面从根路径加载 `/master.css`、`/app.js` 和 `/api/*`。公网入口必须保留这一根路径语义，不能默认改成网站子路径。
7. 监控页面已有 900px 和 370px 响应式断点。网站不得按外层视口宽度隐藏或替换 iframe。
8. iframe 内的按钮、选择器、图表和刷新操作由监控页面自身 JavaScript 处理。网站父页面不转发点击事件，也不读取 iframe 内部 DOM 或应用状态。

## 3. 目标链路与不变量

目标链路为：

```text
用户浏览器
  -> 网站中的监控 iframe
  -> 经批准的 HTTPS 监控公网 origin
  -> 公网边缘或自有 VPS 反向代理入口
  -> 由内网连接器主动建立并维持的出站隧道或私网覆盖网络
  -> prod-monitor-3002
```

无论采用哪一种部署候选，以下不变量都必须成立：

- 连接方向由内网主动发起到公网；公网入口不得主动拨入家庭网络。
- 公网浏览器和 website 构建产物只能看到最终批准的 HTTPS 监控 origin。
- 内网上游地址、设备地址、连接凭据和监控样本不得写入 website 源码、构建产物或本文档。
- 最终公开 origin 必须是独立的监控入口，并从根路径提供页面、静态资源和只读 API。
- 网站与监控入口的 TLS、DNS、访问控制和安全响应头由部署层落实，不由 Vite 开发代理提供。
- 本映射不得改变 `prod-monitor-3002` 的页面设计、交互逻辑、API Schema 或移动端布局。

## 4. 公网 origin 与 URL 契约

### 4.1 生产 URL

- `VITE_MONITOR_URL` 在生产构建中必须精确匹配部署侧批准的唯一 HTTPS origin。
- 最终 origin 尚未裁定时，网站监控区域必须保持未配置状态，不得猜测公网域名，也不得回退到任何内网地址。
- 生产值不得包含凭据、查询字符串、片段、非预期端口或额外路径。
- 示例占位符只用于文档讨论，不能复制为生产配置或 HTML 安全策略。
- 客户端 URL 校验和构建产物扫描只用于防止误配置，不能证明公共域名的实时 DNS 解析目标安全；DNS、边缘路由和 origin allowlist 必须在部署与 CI 层独立验证。

### 4.2 专属入口而非网站子路径

当前监控 HTML 和 JavaScript 使用根绝对路径，因此正式方案采用独立监控 origin。除非未来另一个获批任务系统性修改并验证监控源码，否则不得把监控页面放在网站根域名的子路径下，也不得依赖脆弱的响应正文重写来修补资源路径。

### 4.3 资源与 API 路由

公网监控入口必须在同一个监控 origin 下透明提供：

- `/`：监控 HTML；
- `/master.css`、`/app.js`：恢复版实际引用的静态资源；
- `/api/*`：已审计的只读 API 路径。

代理层必须：

- 保留上游 HTTP 状态码、Content-Type 和既有 Cache-Control 语义；
- 不缓存实时或监控 API JSON；
- 不把 API 错误改写成状态为成功的 HTML 页面；
- 不在重定向、错误页、响应头或日志中泄露内网上游地址；
- 不新增未经审计的写方法或管理入口；
- 不改变 JSON 字段名称、数据类型或数组排序语义；
- 为已审计的长耗时请求保留足够代理生命周期，最终超时值由独立性能验收确定，不能用任意短超时替代应用状态判断。

## 5. 网站托管契约

1. 网站使用 BrowserRouter。生产静态托管必须把 `/dashboard`、`/monitor` 及其他有效 SPA 深链接回退到网站 `index.html`，同时继续正确返回真实静态文件。
2. 网站 SPA fallback 只属于网站 origin，不能应用到监控 origin 的 `/api/*` 或未知路径。
3. Vite 开发服务器及其开发期代理不是生产反向代理；构建产物不得依赖 Vite 进程存在。
4. `/dashboard` 与 `/monitor` 复用同一个监控嵌入组件，不得通过 route key 或等价机制强制重新挂载 iframe。
5. 页面在所有宽度都保留 iframe，让监控页面依据自身 viewport 应用原生响应式规则。
6. 外层网站可以提供加载耗时提示、重试和新标签页打开，但不得把 iframe `load` 事件或计时器描述为 HTTP 成功、API 健康或系统正常。
7. 在没有经严格 origin 校验的 `postMessage` 契约或服务端健康契约前，外层网站不得声称能够读取监控应用 readiness。

## 6. 浏览器安全响应头责任

下列策略必须由实际托管或公网入口的 HTTP 响应头按环境下发，不能把未确定域名的占位策略写入 `website/index.html`：

| 责任方 | 必须落实的策略 |
| --- | --- |
| 网站托管层 | `frame-src` 只允许最终批准的监控 HTTPS origin，不使用宽泛通配范围。 |
| 监控公网入口 | `frame-ancestors` 只允许最终批准的网站 origin。该指令必须来自 HTTP 响应头，不能通过 HTML meta 生效。 |
| 监控公网入口 | `X-Frame-Options` 不得与获批的跨 origin 嵌入关系冲突；不能使用会阻止该嵌入关系的取值。 |
| 公网入口 | 浏览器侧只提供 HTTPS；TLS 证书、续期和私钥由部署环境管理。 |
| 隧道或覆盖网络 | 连接器身份与链路认证由基础设施密钥管理机制保存和轮换，不进入仓库或浏览器。 |

是否向公众开放监控数据、是否需要身份认证，以及哪些 API 字段允许经公网展示，当前均未裁决。部署前必须单独完成数据暴露范围与访问控制审阅，不得假定当前已经存在认证、租户隔离或字段脱敏。

## 7. 部署候选

### 7.1 候选 A：托管应用隧道

内网连接器主动连接托管边缘，边缘持有公网入口、DNS 绑定与 TLS 终止能力，再通过已经建立的出站连接访问 `prod-monitor-3002`。

待核验项目：

- 连接器可安装位置及其最小权限；
- 中国境内三网到托管边缘的实际稳定性；
- 动态出口变化、CGNAT 和多 WAN 切换后的自动重连；
- 连接身份、密钥轮换、日志可见范围及第三方留存策略；
- 自定义域名、证书、访问控制、故障恢复和撤销流程。

### 7.2 候选 B：自有公网 VPS 与受控覆盖网络

内网连接器主动连接用户控制的公网 VPS；VPS 终止 TLS 并提供反向代理入口，通过受控的私网覆盖网络或持久反向隧道访问 `prod-monitor-3002`。

待核验项目：

- VPS 与内网连接器的单点故障、自动重连、保活与告警责任；
- 反向代理、证书、DNS、密钥、日志和补丁维护责任；
- 动态出口变化、CGNAT 和多 WAN 切换后的恢复时间；
- 现有电信 CN2 GIA 双向路径是否确实覆盖选定 VPS 与隧道协议；该路径优势不得推断到移动、联通或其他访问来源；
- VPS 故障或链路异常时的回滚与替代入口。

### 7.3 选择门槛

部署负责人必须基于以下证据裁决 A 或 B，不能仅根据产品名称或单次延迟测试选择：

| 维度 | 最低证据要求 |
| --- | --- |
| 可安装性 | 明确连接器运行主机、最小权限、升级方式和对 `prod-monitor-3002` 的可达边界。 |
| 国内链路 | 分别记录电信、移动、联通的连接成功率、时延分布、断线恢复和连续稳定性。 |
| 交互性能 | 区分浏览器本地点击反馈、普通 API 响应和长耗时监控任务，不以单一平均值代替分位数。 |
| 安全性 | 明确身份认证、密钥轮换、日志脱敏、访问控制和公网 API 暴露范围。 |
| 运维性 | 明确自动重连、告警、证书续期、容量、升级、回滚和责任人。 |
| 所有权 | 明确 DNS、TLS、边缘配置、VPS 和日志分别由谁控制。 |

本文件不选择候选 A 或 B。选择结果必须由单独的架构裁决记录确认。

## 8. 故障与回滚语义

- 公网入口或出站连接不可用时，网站其他页面必须继续工作；监控区域保持未配置或连接耗时提示，不回退到内网地址。
- 代理层应保留真实错误状态，不用缓存的旧成功响应伪装当前健康状态。
- iframe 的 `load` 事件可能对应代理错误页，因此不能单独作为成功判据。
- 连接器重连不得要求家庭出口地址保持不变。
- 基础设施回滚应能撤销公网 DNS/入口与连接器授权，而不修改 `prod-monitor-3002` 页面、数据库、设备或监控配置。
- website 回滚通过恢复上一已验收构建与环境配置完成；不得把内网地址作为紧急兜底重新写入前端。

## 9. 上线前验收门槛

### 9.1 功能

- 通过最终公网监控 origin 加载 HTML、CSS、JavaScript 和全部已审计只读 API。
- iframe 内原有 VPS、时间范围、WAN、协议、路由和带宽交互保持可用。
- 所有监控请求始终指向批准的公网 monitor origin，浏览器网络记录不出现内网上游地址。
- `/dashboard` 与 `/monitor` 的切换不会因人为 route key 重载 iframe。
- 桌面和移动视口均保留监控页面原有布局与功能。

### 9.2 性能与稳定性

- 连接器使用持久出站连接，而不是每次点击临时建立隧道。
- 分别记录页面冷启动、暖缓存、普通 API、长耗时 API 的 P50/P95 和失败率。
- 电信、移动、联通分别验收；电信链路的 CN2 GIA 结果不能代替其他运营商结论。
- 验证公网出口地址变化、单 WAN 失效和连接器重启后的自动恢复；测试不得影响现有正式监控服务。

### 9.3 安全与配置

- 最终 website bundle 不包含内网地址、localhost、开发端口或未批准的监控 origin。
- 网站和监控入口的安全响应头按最终两个 origin 精确配置并通过浏览器验证。
- 公网入口没有泄露内网重定向、错误内容、凭据、客户数据或监控样本。
- 数据暴露范围与访问控制已得到明确人工批准。
- 深链接回退只应用于网站 SPA，不吞掉监控 API 的真实错误状态。

### 9.4 回滚

- 回滚步骤、责任人、触发条件和验证方式已经过人工审阅。
- 回滚不要求修改家庭路由、监控源码、数据库或恢复证据。
- 回滚后 DNS、边缘入口、连接器身份和网站构建均不存在孤立授权或失效引用。
