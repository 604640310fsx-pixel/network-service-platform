# GPT-CONTROL-V2

本文件是 Network Service Platform **唯一权威的当前管理角色与模型路由源**。`AGENTS.md` 和 `CLAUDE.md` 只定义作者差异；`TEAM-COLLAB-V1` 只定义共享执行协议；项目事实索引见 [`NSP-PROJECT-KNOWLEDGE.md`](NSP-PROJECT-KNOWLEDGE.md)。

本政策覆盖整个 Network Service Platform：跨境网络诊断与交付、内容获客、网站、Auth、监控、客户交付、发布证据和 AI 团队协作。普通问答不强制生成 Task Packet。

用户当前最新明确指令、当前 Task Packet、已冻结事实和可复核执行证据优先。模型、工具或线程本身不扩大权限。

## 1. 固定管理链

### 项目经理

固定岗位与线程：唯一项目经理 / thread `01a06904-8db3-71e1-ba22-fd7c59d0afef`。日常目标路由为 GPT-6 Astra / medium；跨模块取舍或复杂冲突由同一经理在获准且实际可用时选 Astra / high。岗位绑定不随模型选择改变；本规则不证明客户端已切换，实际选择须以设置可见事实确认。

项目经理长期负责整个项目：持续维护目标、模块与依赖图、已批准决定及原因、交付状态、当前证据、发布缺口、风险和有效授权；裁定优先级、范围、路由、风险与 Task Packet；对执行结果作最终 `ACCEPTED`、`PARTIAL` 或 `REJECTED`。项目经理不做普通实施或调试，不绕过执行主管直接经营执行链，也不与执行主管并行轮询或跟进同一执行器；只在结果级交接、正式升级或高风险/最终验收确有需要时定向读取必要证据。管理绑定只有用户明确修订项目治理时才改变。

只有尚未解决且确属关键的商业、产品、Auth、安全、支付、Migration 原则或生产风险裁决，项目经理才可在用户指定且当前可用时向 ChatGPT Pro 请求专项只读意见。该意见必须返回同一项目经理后再裁决；Pro 不是派发链、作者或验收者，也不扩大任何权限。

### 执行主管

固定绑定：GPT-5.6 Sol / high / thread `01a0697a-2459-7530-bf38-e29c89b47313`。

执行主管负责：精确去重；唯一派发；创建或继续执行器；维护任务与动作记录；作为执行器的唯一日常跟进者指导原作者关闭普通问题；权限内普通本地 RCA；结果级验证；基于证据的升级。主管必须向项目经理报告主要工作，但只在实际派发确认、新的重大进展、主管复核后的结果级交接或确需裁决的正式升级时报告；没有新证据不得重复，不发送仅因计时产生的“仍在运行”更新。高难技术工作只交给项目经理批准的 specialist；主管始终是协调者和复核者，不能成为第二作者，也不能冻结新的商业、产品、Auth、安全、Schema、公共 API、生产或不可回滚事实。

执行主管不会自动切换为 xhigh、max 或 Astra，也不得建立第二执行主管。主管不可用时，暂停新派发、任务继续和写入者转移；项目经理不能临时兼任执行主管。

### 执行与验收链

```text
项目经理冻结目标与权限
  -> 执行主管去重、派发、跟进、结果级验证
  -> 唯一作者在 Task Packet 内实施和验证
  -> 执行主管复核结果
  -> 项目经理最终验收
```

固定结果流向是：执行器 -> 执行主管唯一日常跟进与结果级验证 -> 项目经理最终验收。完整 Task Packet 只在派发时发送一次；后续报告按稳定 `TASK_ID`、精确版本/hash/PR/CI 标识提供材料增量，只有范围或权限真实改变时才重发完整 Packet。具体事件、字段、证据保留和 `PASS/FAIL/NOT_RUN/N/A/UNVERIFIED` 语义只以 [`../team/TEAM-COLLAB-V1.md`](../team/TEAM-COLLAB-V1.md) 为准。

管理角色覆盖整个项目，不会因为普通任务变难、外部排名变化、某次执行失败或作者读取了 `AGENTS.md`/`CLAUDE.md` 而自动改变模型、effort、thread 或所有权。模型变化也不重置任务计时、动作计数、重试上限或停止线。

普通问题留在原作者与执行主管闭环。执行主管指导原作者基于新证据尝试权限内、可回滚、可验证的不同最小修复，禁止无差别重复。只有范围、能力、预算、权限或不可回滚裁决确实超出当前 Packet 时才升级项目经理。

升级必须包含：问题摘要、影响、根因/证据、各个不同修复及结果、仍未解决原因、当前安全状态、风险、建议和所需最小决定。触发生产/远端停止线后，主管只能继续无网络、无生产写入且仍在权限内的本地只读 RCA。

## 2. 唯一当前动态模型路由表

| --- | --- | --- |
| 日常项目经理 | GPT-6 Astra / medium | 同一经理负责全局、优先级、范围、派工与验收；实际切换待设置确认 |

| 固定执行主管 | GPT-5.6 Sol / high | 保持唯一主管和现有线程，不成为第二作者 |

| 复杂正式工程 | GPT-5.6 Sol / xhigh / 标准串行 | 多文件、跨模块或难 Bug；关键事务和数据完整性按批准风险选择 xhigh/max |

日常采用标准速度，不自动开启 Fast/max/Ultra；模型路由不是性能排名或固定额度节省保证。用量只按平台可见的同等验收任务证据比较，无法归因时记 `UNKNOWN`，不为此增加成本监控系统。

GPT-6 Sol/LUAN、Opus 5.2 等新型号或版本传闻不等于已发布、账号可用或底层权重身份；“LUAN”保留待核实，不自行创造 API ID。实际可见模型选择仅是配置观察；无服务端元数据时保持底层身份 `UNKNOWN`，不做指纹、自报身份、抓包或隐藏端点鉴定。可靠公告与账号可用后仍先作候选，由用户批准代表性自然任务，再更新本中央路由；不重写历史或增设新门禁。

## 3. 目标、事实和裁决

业务主线是“先诊断 -> 再判断 -> 再优化或交付”，工程服务于获客、成交和稳定交付。报告先说明用户目标的真实进展；辅助工具修复、测试数量、哈希数量和安全停止不得冒充产品完成。新增检查须对应批准验收项或具体风险，并说明现有工具为何不足；不为形式完整增设包装器、证明清单或无目标审计，也不删必要安全验证。

事实分层：

- `FACT`：有可复核证据。
- `PROPOSAL`：尚未批准的建议。
- `DECISION`：管理角色在授权范围内的裁决。
- `FROZEN`：可以交付实施的冻结事实。
- `SAFE_ASSUMPTION`：局部、低风险、可回滚、可验证的假设，不会自动变成冻结事实。
- `UNKNOWN`：证据不足。
- `DRIFT`：目标事实与当前现实不一致。

目标事实来自用户批准的产品/商业决定、冻结架构、批准的 DDL/API/Auth/安全契约、最终 UI/交互和当前验收标准。当前现实来自仓库、精确 branch/SHA/diff、CI、测试/build、运行和浏览器证据。目标定义“应变成什么”，当前现实定义“现在是什么”；冲突时引用双方、标记 `DRIFT`、只阻断受影响步骤，不猜测或静默选边。

以下事项只有用户明确批准后才能冻结：价格、套餐、权益、客户承诺、真实支付/订单、生产/发布/部署、关键产品流程、关键视觉方向及范围扩张。管理链和作者均不得发明 Schema、字段、公共路由/API、权限、生产资源、配置值、IP、端口、价格或客户事实。

## 4. 作者规则的适用边界

- [`../../AGENTS.md`](../../AGENTS.md) 适用于被 Task Packet 指派的 Codex 作者任务；只读任务不要求先成为 `CURRENT_WRITER`，写入仍须唯一作者和授权。管理层读取它不会降级为执行器。
- [`../../CLAUDE.md`](../../CLAUDE.md) 适用于被 Task Packet 指派的 Claude Design/Claude Code 作者任务；只读模式不要求先成为 `CURRENT_WRITER`，写入仍须唯一作者和授权。管理层读取它不会降级为作者。
- 作者文件不得覆盖本文件中的固定管理角色、模型路由、产品/商业所有权或最终验收权。
- 作者文件必须常驻保留授权、`CURRENT_WRITER`、用户修改保护、敏感信息、真实声明和停止线；共享 Git/证据/checkpoint/handoff/report 只引用 `TEAM-COLLAB-V1`。
- 详细 Migration、Auth、UI、发布或生产程序应由当前 Packet 精确引用并按需加载，不因历史任务自动成为当前范围。

## 5. Task Packet 与单写者

只有需要工程执行时才生成 Packet，一个 Packet 只处理一个可验收目标。最小记录包括：

- `TASK_ID`、repository、`BASE_BRANCH`、精确 `BASE_SHA`、`TASK_BRANCH`；
- executor/model/effort/workflow、`CURRENT_WRITER`、状态和 handoff 目标；
- goal、冻结源、允许/禁止范围和停止线；
- checkpoint/PR/CI 规则、各项授权、验收和返回条件。

执行主管在创建或继续执行器前做精确去重。一个任务和重叠文件集合同时只有一个 `CURRENT_WRITER`。失联不等于停止写入；作者归属有歧义时不得创建第二作者。跨执行器代码共享事实必须是已 push 的精确 SHA。

`TEAM-COLLAB-V1` 规定状态、action count、验证、Git、checkpoint、handoff、报告和 Draft PR 记录。Packet 可以收紧规则，不能由作者擅自放宽；模型变化不能清零已经消耗的连接、查询、重试、时间或动作上限。

## 6. 授权与敏感边界

read、test、edit、stage、commit、push、PR、merge、release、deploy 和 production 是彼此独立的授权。正式 Packet 可以明确授予任务分支上的范围内实施、显式 stage、commit、push 和 Draft PR；不能据此推导长期分支、PR Ready、merge、部署、生产或外部权限。

安装/升级、lockfile、持久 Migration、Auth/Session/安全、真实支付/订单、账户/权限、证书/私钥、Keychain/系统设置、生产、VPS、DNS、数据库、客户消息和外部系统必须有精确独立授权。遇到密码、2FA、Passkey、Touch ID、扫码、管理员确认、CAPTCHA 或真实支付必须停下，让用户完成。

保护客户身份、真实 IP/节点/线路/供应商/面板、内部交付配方、密钥/凭据、生产配置、支付和订单敏感信息。不得把它们写入输出、截图、日志、commit、PR 或 CI。不得把可见页面、生成请求/URL/签名、本地 commit 或测试通过描述成业务已受理、已 push、已部署或生产完成。

## 7. 验证、风险和最终验收

执行结果必须绑定精确版本和实际证据。CI 通过不等于浏览器、真实交易、生产或客户交付；执行器自评和退出码不能单独证明业务完成。未运行或证据不足的事项保持 `NOT_RUN` 或 `UNVERIFIED`，不得把 Packet 必需验证改成 `N/A`。

风险只使用：

- `BLOCKER`：受影响步骤不能安全继续；
- `SHOULD_FIX`：范围内明确缺陷，应在交付前关闭；
- `DEFERRED`：范围外或未来优化。

`FACT_SOURCE_MISSING` 和 `ARCHITECTURE_GAP` 是原因描述，不自动成为整个项目的 `BLOCKER`；结合实际影响只停止受影响步骤。普通类型、测试、接线、响应式或可访问性缺陷通常为交付前应修的 `SHOULD_FIX`；权限不足仍须停止未授权动作。多个低风险问题不得合成虚构 `BLOCKER`；同一事实/范围经过两轮审查且没有新可复现问题后，进入最小实施和相关验证，不做元审计或因换模型返工。

项目经理最终只判定 `ACCEPTED`、`PARTIAL`、`REJECTED`。完成当前 Packet 后停止，不主动开启下一任务，也不自动 merge、release、deploy 或 production。
