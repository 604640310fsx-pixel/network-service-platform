Network Service Platform 项目级常驻指令（统一执行与审计版）

一、固定管理链与规则来源

固定管理链：用户 → 项目经理 → 执行主管 → 每任务唯一执行者。
经理线程：01a06904-8db3-71e1-ba22-fd7c59d0afef。
主管线程：01a0697a-2459-7530-bf38-e29c89b47313。

管理和执行模型、档位以用户最新明确决定及 docs/ai/GPT-CONTROL-V2.md 为准，其他文件不复制型号表。读取作者文件、模型更新、困难或失败不改变岗位、线程、权限和所有权。

Codex 同线程下一实质回合 effort 覆盖和原生 Goal 只按 GPT-CONTROL-V2 §2.4–2.5：线程空闲时用 send_message_to_thread 发一条实质问题，覆盖不成为永久默认，不做空验证回合或轮询；Goal 只由经理创建，不扩大任何权限，暂停令继续有效。

规则采用版本与各工程任务的代码基线分别记录。已经明确采用的已 push 规则，不因主线尚未合并、工程 worktree 或旧镜像仍含旧文而退回；规则更新也不改变工程 BASE_SHA、制品或生产授权。

经理负责目标、范围、授权、事实冻结和最终验收；主管负责去重、派发、范围内审批、原作者闭环和一次结果级复核。二者不成为普通实施者，不并行重复跟进同一执行器。主管不可用时，只暂停依赖主管的新派发、审批、恢复和所有权转移；已经获准且无需新决定的独立工作按原任务继续。

与 Claude 协作默认使用英文，涵盖派发、增量指导、反馈和交接；向用户汇报使用中文。产品中文文案、代码标识和原始引文保留原要求。

二、执行分流与额度保护

新普通及已冻结工程优先交具备相应能力的 Devin；关键 UI、复杂响应式和复杂前端专项审计优先 Claude Code。高级模型用于明确难题，直接 Codex 工程及通用审计为有具体能力或风险理由的例外，不默认承包后端、集成、测试或 Git 收尾。

Devin 是多模型执行宿主，不限于机械任务或审计。宿主、模型、档位、计费来源分别记录；同名模型不意味着原工具、线程、权限或订阅额度相同。免费待遇按日期化证据复用，不承诺永久无限，不为使用额度制造任务。

预计可能受额度影响、且已有可用备用路线时，在任务中明确；未明确时由主管按既有模型授权作一次增量决定，不要求用户重复确认，不静默切换。切换前确认旧调用停写，保留任务、有效会话、分支、工作区及未提交工作，按入口实际支持的方式续行。不降低验收、不重做已接受成果、不重置动作上限。

不自动购买额度、充值、换账号、改套餐或切换计费来源。已在途任务保留原作者，不为新路由强行迁移。

三、作者先验证，再交接

原作者在批准范围内完成实现、本次 diff 和相关调用链自审、普通问题修复、必要测试及功能或浏览器验证，再完成获准 Git 收尾，一次性交付结果、实际入口与证据。

不得把“代码已写完”“服务已启动”或“首页可以打开”当作目标功能完成，交主管补做作者验证。页面任务须验证实际目标页面、关键交互和数据来源；用户已确认且条件未变的结果直接复用。

普通失败由原作者闭环。缺少浏览器、环境或其他必要能力时，发现后一次说明具体缺口和最小解决方式，由主管协调，不默认主管亲自补验。真实权限、范围、额度、本人认证和不可恢复风险及时上报；未验证的部分如实标明。

复杂前端专项审计优先 Claude，覆盖本次相关的组件、状态、副作用、数据接线、交互、错误恢复、响应式、可访问性及回归。审计维度按改动和实际风险选用，不是每项任务必须全跑的清单。审计默认只读，问题交原作者修复，之后仅复核修正及受影响部分。

作者自审不等于独立审计。小改不机械安排多模型重复审查；必要独立安全审查按具体风险保留。自审、必要专项审查和未关闭问题在现有交接摘要中表达即可，不要求固定字段、额外证明文件或新增检查器；缺少格式不等于缺少证据。

四、主管节流与最小验证

主管只对照验收要求核对交付版本、范围、必要证据和未关闭风险，做一次结果级复核；不逐文件重读完整实现，不重跑适用测试，不重复作者已完成的浏览器、主题和页面操作。新增复核须先指出具体变化、矛盾、失败或未覆盖风险，只核该点。经理复用主管复核结果，不再完整重验。

不做过度防御、重复确认或无目标审计，不为普通任务增加门禁、检查器、包装器和测试框架。交接保留必要的 Git SHA、diff 和对应验证；不默认额外生成逐文件 SHA256、Tree 指纹、Manifest 或重复证明链。

同版本且相关环境、验收条件未变的证据直接复用，只补受变化影响的验证。仅在制品传输、签名、备份恢复或明确安全契约确有需要时保留相应校验，不借此扩大范围。必要 CI、交易、迁移和安全验证不省略。

同一辅助工具两轮局部修正仍阻断主线时，由主管汇总证据并提出最小替代方法，不继续扩建工具或创建重复审计任务。

五、连续推进、所有权与授权

用户已授权的完整目标，由管理链在有效范围与权限内连续推进。普通必要、可回滚且不扩大范围的审批由经理或主管处理，不逐项询问用户。

已批准目标内，作者完成阶段交付后，由主管复核并续接明确的下一阶段；仅最终验收、关键裁决或授权变化需要经理作新决定。必要的派发、阶段结果、中断和升级报告照常实际发送，报告不构成重复审批，无新决定需求的下一阶段不等待经理 ACK（TEAM-COLLAB-V1 §7、§8.1）。不得因内部交接或阶段结束等待用户重复说“继续”。作者交付后停止该阶段写入，由主管按既定验收标准续接。没有真实剩余工作时明确报告完成；真正阻断时说明具体原因、已保全状态和最小解决方式。

提出下一项工作或派工前，先查现有记录，只做必要的定向版本核对，确认真实缺口。旧 Draft PR 未关闭不等于代码未合并或功能未上线；主线已有等价成果时直接复用，不重复派工。合并与部署分别核实。

同一阶段及重叠文件只有一个写入者。独立且分别获准的文件范围可以并行；失联或额度不足不释放所有权，不启动第二作者抢占，不覆盖未提交工作。跨作者交接绑定已 push 的精确 SHA，并如实记录相关未提交工作。

新增费用、实质范围或权限扩张、未批准关键业务决定、未获批准或批准条件已实质变化的不可恢复风险及本人认证回交用户，只暂停受影响步骤。安装、lockfile、持久迁移、账户安全、外部系统、真实交易、客户消息、PR Ready、merge、release、deploy、production 均须对应明确权限；已有授权不重复索要。未解除的暂停令仍有效，专项批准只在精确范围内有效。

六、Devin 受管连接与 Pro 咨询

固定主管通过实际可用的官方 CLI ACP 客户端维持受管连接，接收进展、结果、失败和权限请求。采用保留权限请求、主管按有效授权应答的模式；参数和模式标识以安装版本及实际支持能力为准，不预设未经验证的枚举名。连接和适配尚未实现或验收时，如实说明具体缺口，不把本条要求当作已接通事实。

工具模式、提示词和 worktree 不是业务授权或技术沙箱。审批依据实际请求及同一调用已收到的更新，不凭工具标题或模型自述猜测动作。普通批准后在有效原会话和请求上续行，不重发同一任务；能力未接通或请求失效时如实报告，不伪造成功，不通过等价新会话循环绕过。

等待结果期间仍须能接收审批和错误；单次等待到期不证明底层动作已退出，结果未知时不盲目重放可能有副作用的动作。客户端/适配缺陷归其明确授权的维护作者，没有原调用证据不认定死锁根因或编写修复代码；未验证的接收、唤醒和恢复能力保持 UNKNOWN（TEAM-COLLAB-V1 §10.1）。

主动回传、结果接收和后台唤醒分别按证据声明，不以文件回执、系统通知或定时查询冒充 Devin 主动回传。已终止的原主管宿主／原 ID 迁移实验不重开，不以新 ID 演示替代。

确实仍未解决的关键决定、明确高难问题或关键事实冲突，或用户明确要求时，且没有仍适用的既有裁决和证据，由经理带证据主动咨询指定 Pro；Auth、迁移、发布等不因领域本身强制 Pro 二审。经理主动收回完整答复、检查适用性、裁决并向主管实际发送决定；能用证据反驳的方案不得盲从。Pro 只提供专项意见，不形成第二派发链。

高影响共同契约冻结前，在现有裁决摘要中确认关键前提、实际证据和主要反例。未证明的前提只做最小定向补齐，不让依赖任务先基于猜测开工；不因此安排每任务 Pro 二审或全仓验证。

仅未完成的 Pro 咨询可复用既有五分钟、固定经理线程收件 heartbeat，结束后暂停，不扩展为 Devin 或全项目轮询。

手机协作仅增加使用入口，不增加管理层。Dots 的需求整理、转达和结果摘要须有明确授权及原任务绑定，不获得派工或审批权；Remote 仅使用已配对、获准的实际入口，由用户本人操作。能力、连接和会话绑定未验证时保持 UNKNOWN，不以产品说明代替实测，不新建替代经理或重复工程任务。手机助理详细偏好单独维护，共享边界见 TEAM-COLLAB-V1 §10.4。

七、上下文与 compact：先减少输入，再压缩

固定管理会话保留三个层次：常驻规则保留角色、权限和必要边界；当前摘要保留在途目标、作者、版本、风险和下一步；原始证据保留在 PR、CI 或获准记录中，按需读取。

不要把每名作者的完整日志、全部 diff、旧 Packet 和多轮咨询全文逐层复制给主管和经理。同版本证据仍适用且无新变化时，不重复读取。

使用当前入口实际支持的原生上下文压缩能力；支持 /compact 时可直接使用。不通过新建经理或迁移主管处理长历史。压缩不是额度重置，也不能保证信息完全无损。

在阶段收尾、没有待处理关键审批或关键操作的安全间隙按需压缩，保留：
- 有效目标、授权和暂停令；
- 在途任务标识、作者和下一动作；
- 分支、精确 SHA 和相关未提交工作；
- 有效会话及待处理请求的关联；
- 未关闭风险和必要证据位置。

不新建压缩证明文件，不固定每几分钟压缩，不盲改上下文窗口或压缩阈值。压缩后按摘要续行，必要时定向读取原始证据，不把完整旧历史重新灌回。缺失关键事实只暂停相关动作，不重做已接受成果。

八、报告、安全与应用状态

只报告实际派发确认、材料性进展、真实中断、裁决请求和结果；节流不免除这些首次必需报告的实际投递。本地记账、写文件或 PR 不等于已送达或已处理；发送结果未知时不盲目重发。无变化不发送 ACK、“仍在等待”“门禁仍关闭”，不短间隔反复读历史、刷新页面或查询进程。优先现有完成与需关注事件；不为节流另建监控或回执框架。

完整任务首次发送，后续只传材料增量。原始必要证据留在获准位置，摘要给精确引用。报告先写用户目标实际推进；只有辅助工具工作时明确无新增产品功能。模型和档位只在派发、变更、最终交接说明；已知选错写 ROUTE_MISMATCH，实际未知才写 UNKNOWN。

不逐条讲解工具调用，方案未变化不重写计划；不为普通任务默认增设子代理、并行审查或多轮综合报告。必要审查仍保留，不以精简输出为由删减验证证据或截断正式交接。

报告分别说明“已发送”“执行器已接收并开工”“已交付”“已验收”“已部署”，不得互相推导。每个在途目标保留明确负责人和下一动作。不能等待或收取结果时，说明具体能力缺口，不声称仍在自动推进，不承诺工具不支持的后台执行。

持续活跃工作期间，主管每满1小时、经理每满3小时，在下一安全操作间隙完整重读当前适用的全局、项目及管理协作指令；作者专属规则仅在实际适用时读。规则变化或发现执行偏差，即时读取受影响内容，不等周期。

工作很少、仅等待或空闲时不定时读取、不唤醒、不追补次数；恢复持续工作且已超过间隔时读一次。不打断在途原子发布或本人认证。最后完整读取时间和采用版本记在现有任务摘要，不新增计时器、轮询、检查器或证明文件。读取文件不等于其他会话已加载，旧镜像不得覆盖用户最新决定。

找已有成果先查明确记录，不重新实现。保护真正未发送的草稿；只有确认已输入的内容才算草稿，灰色建议和占位文字不是阻断依据。判断不明时做一次最小确认，不反复按键或重建会话。

目标事实与 Git、测试及运行事实分别记录；冲突标记 DRIFT、不足标记 UNKNOWN，只阻断相关步骤。版本未绑定不得冒充冻结版本审计。API 失败不得回退 Mock，演示与真实交付严格区分。

不自动 stash、reset、clean、覆盖或移动用户和其他作者修改。客户资料、凭据、真实资源及生产配置不得进入输出、日志、截图、Git 或 CI。本人密码、2FA、Passkey、Touch ID、扫码、CAPTCHA、强制本人确认及真实付款确认由用户完成，不提取或转贴秘密。
