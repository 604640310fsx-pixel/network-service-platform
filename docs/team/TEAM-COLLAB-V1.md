# TEAM-COLLAB-V1

本文件是原 Network Service Platform 的共享执行协议：任务事实、唯一作者、验证、Git、handoff、材料报告和受管审批。管理角色、模型/宿主/费用/上下文政策只见 [GPT-CONTROL-V2](../ai/GPT-CONTROL-V2.md)。本文件不扩大产品、外部、Git 或生产权限；用户最新决定和有效授权优先。

## 1. 任务与事实源

正式工程任务在现有 Packet/摘要中绑定 `TASK_ID`、repository、base branch/精确 `BASE_SHA`、task branch、冻结目标与范围、`CURRENT_WRITER`、状态、必要验收/CI、各项授权、风险和下一动作。目标事实来自批准的商业/产品/契约/UI；当前现实来自实际 branch/HEAD/diff、测试、CI、浏览器和外部证据。两者冲突标 `DRIFT`，缺关键证据标 `UNKNOWN`，只暂停依赖步骤；不以主检出旧规则否定已采纳的可追溯规则版本。规则版本与工程 `BASE_SHA` 分开。GitHub 已 push 精确 SHA 才是跨执行器共享代码事实；本地 dirty 与聊天摘要不是。

开始或接手前，定向核对实际 repository、remote、base、HEAD、status、相关 dirty、作者和范围；同版本且状态未变的核验直接复用。只读审查须绑定输入版本，不能绑定则标 `UNVERIFIED/STATIC_ONLY`。已有记录能证明完成时不重复派工；旧 Draft PR 未关闭不说明修复未入主线，部署事实另证。

## 2. 状态与唯一作者

`READY → IN_PROGRESS → VALIDATING → HANDOFF_READY → DONE`；依赖步骤可 `BLOCKED`，撤销或命中不可继续的停止线为 `STOPPED`。作者不得自判最终 `DONE`，`HANDOFF_READY` 不是经理验收。普通审批/本人认证等待在原任务中标原因，获准且原请求有效时继续；失效请求不能伪装恢复。

一个任务、阶段及重叠文件集合同时只有一个可定位的 `CURRENT_WRITER`；`NONE` 表示无人写入。写入还要有该范围的 edit 权，不因角色、模型、工具模式或“全权限”字样获得 Git/外部权限。主管、经理和只读审查者不得同时修改作者文件。失联、额度不足或超时不证明原作者停写；转移前须确认停写和 branch/HEAD/diff/dirty/授权，跨作者按 §6。主管不可用只暂停依赖其新决定的步骤，经理不兼任主管；独立获准工作继续。模型切换不重置动作、计时、重试或停止线。

## 3. 证据与 checkpoint

`ACTION_COUNTS` 只记录 Packet 限额或实际风险所需的连接、交易、commit/push 等，不为普通读取/编辑/本地测试建立计数框架。Checkpoint 是逻辑阶段的证据，不是新授权；短任务可在同一交接中合并基线、验证和结果。push 前及 handoff 的必要证据不能省。现有任务摘要或 PR 记录任务/作者、base/HEAD、变更、实际验证、风险/未知、相关 dirty、一个下一授权动作；不另造证明文件或固定字段矩阵。失败须保留并区分本次新增、相关既有、无关既有、环境和外部原因；不以新 checkpoint 覆盖失败。

## 4. 验证

`PASS` 为当前版本实际运行并满足要求；`FAIL` 为已运行不满足；`NOT_RUN` 为未运行；`N/A` 仅客观不适用且非 Packet 必需；`UNVERIFIED` 为证据不足或不能绑定当前版本。Packet 必需项未运行不得写 `N/A` 或虚假 PASS。方法、环境和 HEAD/制品版本须可复核。CI 成功不等于浏览器目标、真实交易、部署或客户交付。

文档/局部配置通常用 status、范围 diff、`git diff --check` 和相关结构检查；产品代码做受影响组件检查、必要测试及实际目标功能验证；跨组件或外部 E2E 仅在范围和授权明确时进行；生产验收只随单独生产授权。同版本、条件及验收未变时复用证据；修复后重跑受影响检查。额外测试、独立审查和安全/资金/数据/支付/CI 门禁依具体变化、失败或未覆盖风险，不默认全量矩阵。辅助工具两轮不同的局部修正仍挡住目标时，选择已有获准最小替代方法或提交最小裁决，不扩建工具，也不放弃范围内普通产品 Bug。

## 5. Git、用户工作与授权

`read → test → edit → stage → commit → push → PR → merge → release → deploy → production` 各自独立授权；前一步不蕴含后一步。安装/升级、lockfile、持久 Migration、账户/安全、外部系统和费用同样需对应授权。普通必要可回滚审批由经理/主管在用户已授目标和权限内处理，不逐项问用户，也不以可回滚推导生产权。

保护用户及其他作者文件；不自动 stash/reset/clean/restore/覆盖/搬移，不查看无关私有内容。白名单范围只编辑与显式 stage 获准路径，禁止 `git add .`/`git add -A`。独立 worktree 保护改动，不是系统/网络安全 sandbox。push 前核 branch、remote target、base/HEAD、最终 diff、敏感门禁及必需验证；失败代码不为产生 handoff SHA 而 push。PR 默认 Draft 且 base 匹配 Packet；长期分支、force push、PR Ready、merge、branch 删除、release、deploy、production 分别授权。既有服务器/生产暂停令一直生效。

## 6. Handoff

短核心报告绑定 `TASK_ID`、状态、来源/目标作者、执行宿主及请求/可见实际模型（不可见写 `UNKNOWN`）、base/branch/精确版本、修改路径、实际验证、风险、相关 dirty 与一个下一授权动作；按需补 Packet/PR 条件证据。代码跨作者交接必须使用已 push 精确 `HANDOFF_SHA/REMOTE_SHA` 且相关未提交工作为 `NONE`；未授权 push 则如实标仅本地成果，不伪造跨作者代码交接。设计/本地制品按获准入口和稳定版本标识，不能假作 Git 提交。原作者停止写入后，主管显式转移；接手者核对版本/范围/权限/dirty。冲突只暂停受影响交接，不通过覆盖、stash 或第二作者绕过。

交接前用现有摘要对照当前请求、实际结果和证据；ACK、计划、摘要或“已发送”均不代表实施或完成。作者偏离目标由主管定向纠正，主管偏离目标由经理定向纠正；以随后实际动作或交付证明纠正已生效，不为此设置逐步审批或重复全量复核。

## 7. 材料事件报告

主管是作者唯一日常跟进者；经理仅在正式升级、重大结果、实际中断及最终/高风险验收读取必要证据。完整 Packet 首次发送一次，后续按稳定任务号与精确版本报材料增量。首次实际派发/接收、重大进展、主管一次结果级复核后的交接、需裁决升级，以及真实中断与恢复，分别在出现时报告一次；节流不取消这些首次报告。普通小进展可合并，无变化不发 ACK、“仍在等”或 timer-only 更新。发送、执行器接收/开工、交付、验收、部署分别取证，不由前一状态推断后一状态。报告不构成重复审批，已批准下一阶段不等经理 ACK。原始证据留在获准任务、PR、CI 或 evidence 位置，摘要仅给可复核引用，不复制敏感日志。

等待优先消息事件；必要时用受支持有界等待与 cursor，不空轮询、短间隔复读或新建监控框架。实际停工、额度/平台中断、作者退出、权限或单写者卡住时，主管及时报任务、影响、保存状态、恢复路径和所需最小决定；硬中断无法发送则恢复后补报，不假称后台自动推进。无剩余真实工作就明确完成。升级只提问题、证据、影响、已尝试不同路径、当前安全状态与最小决定；普通 Bug 留原作者闭环。

### 7.1 协作语言与事件驱动恢复

与 Claude 协作默认英文；用户报告中文，用户指定文案、引文和代码按原样。恢复新任务、压缩或中断后，复用当前会话已实际注入/读取且仍适用的指令和现有任务摘要，恢复目标、授权/暂停令、作者、已验收与剩余工作、规则及工程版本、相关 dirty、有效会话/审批请求、风险和下一动作。规则仅在缺失/变化、角色或工作区漂移、发现执行偏差时定向补读；无新回合强制磁盘开头读取，也无主管每小时/经理每三小时全文复读。文件存在、push、ACK 不等于其他会话/UI 加载；规则变化不解除暂停。上下文具体窗口/压缩只见 [GPT-CONTROL-V2 §4](../ai/GPT-CONTROL-V2.md#4-上下文窗口压缩与恢复)。压缩后依据摘要续行，缺口只暂停依赖步骤，不重放副作用和已接受工作。

接到新目标或从另一事项返回时，先用现有摘要确认当前结果、授权/暂停和下一动作；首个实质动作推进当前目标或其必要前提。旧目标、参考材料或迟到结果不自动变为当前任务；不以逐步 ACK 或仪式性重读代替推进。

## 8. 问题闭环与升级

普通工具、脚本、测试/build、类型、参数/路径、数据接线及机械 UI 问题由原作者用新证据闭环；不因普通失败或工具批准停主线。范围、能力、费用、敏感契约、不可回滚风险或环境确实超出时，保全并按 §7 升级。模型变化不能重试相同失败或清零停止线。不能取得结果时明确能力缺口，不能声称仍自动推进。

### 8.1 作者一次交付与主管节流

本节是作者完整执行/验证和主管节流的唯一主条款；中央路由和作者文件只引用。作者先查已有同目标实现、预览、PR 和同版本适用证据。获准作者连续实施目标、自审本次 diff/直接调用链/边界/错误处理，修复范围内普通缺陷，完成直接相关测试、必要目标页面/核心交互/真实数据来源验证及获准 Git 收尾，再一次交付可用入口和证据。服务启动、首页可开、代码写完或静态推断不能替代目标验收。缺工具/浏览器/依赖或越权时，一次说明精确缺口、已完成部分、最小决定；相应结果保持 `NOT_RUN/UNVERIFIED`。自审不冒充独立审查。

具体跨模块/共享核心、复杂状态/恢复、反复实质修复、身份/权限/CSRF、资金/账本/结算、幂等/并发/回滚、Migration/既有数据、不可逆外部副作用或明确验收要求时，按实际风险选择聚焦独立审查及必要动态负测；复杂前端专项优先 Claude，审查默认只读、原作者修复、只复核受影响部分。小改不强制多模型审查；同版本已覆盖的结论复用。必要支付/Auth/数据/迁移安全及 CI 不省略。

纠偏观察者须在现有任务记录/摘要（已有 Packet 则复用）中明确独立只读角色，与本任务作者互斥；作者自审不算独立观察。仅在路径选择且返工代价高、辅助工程反复无实际进展、估时明显超出或用户质疑时按需启用；小任务不默认启用，不重审已验收成果，不为接入新造演示或评测。输入原始用户目标、最新授权/暂停、当前目标与下一动作及必要真实行动/结果，不能只用 Codex 摘要或全量历史；输出具体偏差、证据、影响和最小纠正，无偏差即结束。观察者不派工、写入、审批、停止作者或解除暂停；涉及主管自身偏差的观察原文及证据须完整送经理，由经理裁决、主管指导原作者，实际后续行动按 §6 证明纠正。

主管只作一次结果级复核：核版本、范围、作者自审、必需功能/动态测试、触发的独立审查及未关闭风险；不成为第二实施者或重复跑同样页面/主题/测试。矛盾只核对应点，缺作者验证退原作者补齐；修复后定向复验。内部编号、branch、报告字段由负责人按现有证据补，不向用户索要。额外审查/记录只为具体未覆盖风险。已批准阶段出结果后主管收件复核并续接，最终验收或关键裁决交经理。只有真实剩余工作才继续；不制造任务或过程框架。

## 9. 风险、停止线与敏感信息

风险只用 `BLOCKER`（受影响步骤不能安全继续，说明解除条件）、`SHOULD_FIX`（范围内缺陷，交付前修复）、`DEFERRED`（范围外/未来优化）。base/repository/作者漂移、用户修改冲突、范围外必需修改、未授权依赖/lockfile、Auth/安全/资金/订单/Migration/外部/生产、不可修复的必需验证失败及无授权 merge/deploy/删除/强制更新，只停受影响步骤；`FACT_SOURCE_MISSING/ARCHITECTURE_GAP` 仅在确有依赖时阻断。不得伪造证据、静默回退 Mock 或启动第二作者绕过。

秘密、真实客户/资源/IP/线路、生产配置、支付订单信息在输出、截图、日志、Git/CI **生成前**最小化；不读取或代输密码、2FA、Passkey、Touch ID、扫码、CAPTCHA、强制本人确认和真实付款确认。普通工具批准不等于本人认证。服务器/生产暂停令不能由规则更新、工具批准或其他任务授权解除。

## 10. 受管连接与审批

### 10.1 Devin 受管连接

Devin ACP 方向须由固定主管持有实际受管双向连接；CLI 已装/已登录、配置文本、工具标题或安全 prompt 不证明连接、回传、权限或隔离已生效。入口、宿主、模型/effort、计费、session/请求及已验证能力分别绑定日期化事实；`UNKNOWN` 只影响依赖能力的步骤。默认保留权限请求，不用 Bypass/Full Access 绕过。Ask 为静态阅读，Plan 为未冻结方案；Desktop Smart 与 CLI/ACP 模式不混同。

对单个工具请求，主管看实际动作、参数、副作用、同一调用已收到的更新和当前授权，选择**该请求实际可见且合规的选项**应答原 request；不得猜界面选项索引、凭标题把 `git *`/解释器/包管理器整类放行。一次普通批准只覆盖该动作；`persistentRemember` 或同类持久允许必须另有明确授权，不能由单次批准推导。证据不足不放行，也不切模式或新建 session 绕过。批准后原会话/请求仍有效则续行，批准不是 STOP；本人认证、费用或实质扩权只暂停相应请求。

用原请求结果，或在结果不足时做一次最小观察，确认实际生效选项。若结果与意图不符，立即停该动作，在既有权限内定向纠正，不保留误授权限；同一选择方法反复出错时，未修正方法前不得照旧继续。

工具 completed、进展通知、权限请求、最终结果、错误/退出分别处理，不把其中一个当任务完成。底层动作超时不等于已停，先查原调用返回与取消/退出证据；可能有副作用的 push、Migration、订单、部署不得盲目重放。断连或请求失效保留作者、branch/worktree/dirty/验证并报最小恢复缺口，不重发同目标任务。日志/文件/系统通知/截图不代替主管实际收到结果；不定时轮询 Devin 或新建后台框架。接入能力只在一次真实小任务所覆盖的范围内标已验证；不能承诺 inactive 宿主后台唤醒。

### 10.2 Pro 咨询收件的唯一定时例外

经理咨询 Pro 后须取回完整答复并裁决。优先实际消息；仅有未完成咨询且需延后收件时，可复用用户已批准的固定经理线程五分钟 heartbeat，咨询结束后暂停。它不授权 Devin 轮询、其他定时器或管理迁移；无新答复不重复广播。收件失败只报告具体缺口。

### 10.3 状态与手机入口

首次实际使用新入口或有失效证据时核实必要能力/费用，复用仍适用的登录和模型事实；不提取 Desktop 凭据、重复登录、购买或切计费。实际发送、接收、审批应答和最终结果各凭证据声明。Dots 若单独获准仅转达与摘要，不获得经理/主管/作者/审批权；Remote 本人确认由用户进行。手机入口不代替受管连接或解除暂停。
